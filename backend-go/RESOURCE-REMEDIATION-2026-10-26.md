## 升级与部署合同

1. 服务端和客户端需配套更新。旧客户端按发布码构造的 `/live/{key}.flv` 会被拒绝；新客户端从认证 watch 接口领取 URL，再按当前连接访问本后端 `/live`。
2. 发布码按需求为八位；已有八位码不因重复下载配置而变化。上一轮产生的 32 位码须由房主重新下载配置，首次下载原子迁移为八位；OBS 中的服务器/密钥应成对更新。转交房主后须使用新房主配置。HTTP 隧道并不自动开放 RTMP TCP 入口；必要时配置独立 `SERVER_HOST` 和可达推流端口。
3. 海报能力有期效：目录重新浏览、重新读影片快照可续签；房间关闭、影片/挂载删除或资源身份改变会拒绝旧能力。海报能力是限用途 bearer URL，可被持有者使用至到期；它不等于业务登录令牌，不能调用其他 API。
4. 新增/改路径的服务器文件分享限 root；普通观众使用已授权 movieId 播放。原生媒体的 HEAD/Range 语义保留。
5. 外置 NMS 的直接 RTMP/HTTP 端口由外置服务自行鉴权及限制网络访问。本项目已保护后端 `/live` 与内嵌媒体面，不能替外置媒体服务配置访问控制。
6. R02 的实际拨号检查及 R03 的代理连接池复用已随明确代理修复落实；R01 CORS/CSRF、R03 其他业务响应预算、R04 外置 TLS LiveKit、R05 首次管理员策略仍为原审查中的独立事项，未在本补丁中作无边界改动。

本轮构建产物用于本地客户端和 GUI 同步，不代表 GitHub Release 或 NAS 已更新。测试夹具、日志、用户提供的排查材料、安装包及签名私料不随源码提交。
