# Go 服务端重构后缺陷检查与修复（2026-10-25）

## 范围与基线

检查 `backend-go` 的房间、Socket.IO、播放记忆、音乐、挂载直链、鉴权和 HTTP 路由，
并修复本地浏览器实际复现的配套网页播放器删除同步；
修改仅限服务端仓库。本地起点是 `9561f34b78de2a3a06f928fddc7b262315c03605`，
它包含两条先前已有的本地修复。本轮提交保留这些既有工作，上游 PR 单独承载本轮补丁。
测试使用隔离的 SQLite、上传目录和回环监听，不连接或修改 NAS 部署。

## 已复现并修复的问题

| 编号 | 问题与实际影响 | 修复与回归入口 |
|---|---|---|
| 1 | **播放清理自死锁**：30 秒清理任务持有播放缓存锁，再通过房主在线回调重新获取同一把锁。出现播放状态后即可阻塞后续心跳与播放操作。 | `playback.go` 在锁外调用在线判定；`TestBroadcasterCleanupDoesNotDeadlock` 运行真实广播器清理调用链。 |
| 2 | **房间状态数据竞争**：`State` 解锁后，影片列表、当前影片、字幕和播放状态仍被无锁写入；读写还共享切片。 | 在同一互斥锁内完成写入，读写列表都复制切片，状态返回快照；`TestRuntimeStateConcurrentAccess`、`TestRuntimeStateOwnsMovieSlices`。 |
| 3 | **Socket 身份数据表竞争**：待审批标记、身份读取和广播快照访问同一张 map，复制 map 时也没有加锁，存在进程级并发 map 读写风险。 | `GetData` / `SetData` / `DeleteData` / `DataSnapshot` 统一持锁，替换业务侧直接访问；`TestSocketIdentityConcurrentDataUpdates`、`TestSocketDataSnapshotConcurrentAccess`。 |
| 4 | **音乐状态与时长错配**：外推直接读取正在被写入的缓存；旧曲目时长查询结束后可能覆盖新曲目的缓存。 | 锁内取播放快照，按该快照的曲目解析时长，只有曲目仍相同时回填缓存；`TestMusicAdvancedStateConcurrentWrites`、`TestMusicStaleDurationCannotOverrideNewTrack`。 |
| 5 | **新进度被旧落盘误标为已保存**：用毫秒时间戳判断是否是同一份状态，同一毫秒内的不同视频/音乐更新会误清 dirty 标记，重启后恢复旧进度；并发 SQL 也可能乱序完成。 | 增加独立 revision，比较缓存条目与 revision；串行化落盘、房主连接更新和清除；清理前复核条目。两项 `*FlushPreservesConcurrentUpdate` 测试用真实 SQLite 阻塞在途写入，修复前最终落盘 1，修复后为最新值 2。 |
| 6 | **跨房间踢人**：只凭目标 Socket 在线即可结束其会话并断开，未确认目标属于当前房间且是观众，房主也能被当作观众踢掉。 | 先查本房间有效 viewer 会话，再结束具体 session；`TestKickViewerRequiresActiveViewerInSameRoom` 覆盖本房间/其他房间的房主和观众。 |
| 7 | **转交房主越过会话边界**：角色更新只限制 socketId，可能修改其他房间与历史已结束会话；无有效目标也照样修改 owner。 | 事务内要求房间 active，角色更新限定房间、有效会话、目标 userId，必须恰好各更新一条，否则回滚；`TestTransferHostRejectsUnrelatedOrEndedSession`、`TestTransferHostPreservesEndedSessionHistory` 及已有正常转交测试。 |
| 8 | **直链错用其他用户挂载和缓存**：按服务器地址任取挂载，并仅按服务器/路径共享签名直链，不同账号的同一路径会互相污染。影片自身凭证的优先级也与流代理相反。 | 优先绑定的 sourceMountId，历史数据只回退房主挂载；影片凭证覆盖挂载默认值。以目标、有效凭证和 HTTPS 偏好的摘要隔离缓存；`TestDirectResolveCredentialIsolation` 覆盖双用户、历史记录、显式凭证和挂载删除。 |
| 9 | **多人直链解析返回空成功**：共享 channel 只发送一个结果，关闭后其余等待者读到零值；取消的请求也会一直等上游。 | 结果存于共享调用对象，关闭完成信号通知所有等待者，并监听等待者 context；`TestDirectResolveConcurrentWaiters` 覆盖 12 个并发请求的成功与失败，`TestDirectResolveWaiterCancellation` 覆盖取消。 |
| 10 | **修改 OpenList 密码仍复用旧登录令牌**：登录缓存只核对服务器与用户名。 | 命中时同时比较密码摘要，凭证变更立即重新登录；同一 `TestDirectResolveCredentialIsolation` 覆盖同用户名改密码。 |
| 11 | **Socket 重复连接与幽灵成员**：鉴权期间关闭会话后仍发布连接；同一 Engine.IO 会话并发 CONNECT 可注册多个 Socket；进退房间的两张索引分开更新会留下幽灵成员。 | 发布前在会话锁内复核，原子发布索引；成员变更统一锁序，先标记断开再清成员；`TestCloseDuringSocketAuthentication`、`TestConcurrentSocketAuthentication`、`TestConcurrentRoomMembershipAndDisconnect`。 |
| 12 | **清理调度器无法独立停止**：停止 ticker 不会唤醒仍等待父 context 的 goroutine，stop 只能等超时，任务泄漏。 | 调度器持有自己的可取消 context，stop 用 `sync.Once` 取消并停表；`TestCleanupSchedulerStopCancelsOwnContext` 及已有停止测试。 |
| 13 | **删除当前影片后继续播放**：真实浏览器中 REST 删除成功，观众仍继续播放。后端未清理旧播放记忆；网页房主忽略恢复期的空影片广播，观众清过元素后又能被旧快照重新挂载。 | 删除当前影片时清空后端播放记忆与字幕；网页根据权威影片列表清除已删除选择，并同时清空播放源快照，保留无影片 ID 的预览播放；`TestBroadcastMovieListClearsDeletedPlayback` 与双浏览器复测。 |

原有 `go test ./...` 全部通过后，以上新增回归仍复现了缺陷，说明接口数量对齐和已有单测
不能代替对 Go 并发、事务边界和生命周期的检查。本轮新增 20 组顶层回归测试，并保留原有测试。

## 验证记录

- Go 1.26 / Windows amd64：`go vet ./...`、服务端 `go build`、`go test -race ./...` 通过。
  33 个有测试的包通过，另有 6 个包没有测试文件。
- 前端 `npm run build:frontend` 通过；保留的构建提示是依赖 ESM 和大分包提示，没有构建错误。
- `npm run test:media` 15/15、`npm run test:music` 10/10 通过。
- 对独立本地服务运行历史路由契约探测：189/189 均未落入“接口不存在”兜底。
  静态事件契约对照：65/65 个业务事件已注册。此项证明覆盖，不单独证明每条业务都正确。
- 使用 ego-browser 的两个独立本地域名分别作为房主和游客，播放无音轨的 MP4。
  连续播放期间跨过多轮 30 秒清理，观察到 146 次同步心跳；超过 3 分钟后仍能暂停、
  跳转到 15 秒并继续播放。暂停时两端进度差约 0.10 秒，继续播放时约 0.03 秒。
- 真实媒体 Range 请求：`bytes=0-1023` 与末尾 512 字节均返回 206，
  Content-Range 和实际字节数相符。
- 删除当前影片：修复前两端列表移除后仍播放；修复后两端移除 src 属性、暂停，
  `readyState=0` / `networkState=0`，延后请求播放状态也不恢复已删除源。
  浏览器验收使用实际 video 元素、页面状态和 Socket ACK；本地记录不包含真实账户数据。

## 验证边界

本次没有更改数据库结构、升级依赖、修改 Android/HarmonyOS/iOS 客户端，或部署 NAS。
直链与并发场景使用受控上游响应和隔离数据，不等同于真实 NAS 上的 OpenList、WebDAV、
Emby/Jellyfin、Bilibili 会员内容和外网 LiveKit/NMS 的逐源验收。
本轮结果不构成“全部服务端已经不存在其他 bug”的保证。
