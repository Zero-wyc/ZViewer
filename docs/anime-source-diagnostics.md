# 聚合番剧源诊断与修复记录

检查日期：2026-10-12。基线为上游 main 提交 `46fe8d585cdb9a96bfc4c8378a38af3d981e0148`。在电脑本地启动服务端，以隔离数据库进行检查。

## 海报问题的原因

Kazumi 与 ani-subs 的 DTO 已声明 `cover`，但两个 provider 的搜索实现没有提取、传递海报。修复前，DM84 搜索「辉夜」返回 7 条结果、0 个 cover；森之屋返回 7 条结果、0 个 cover。这是服务端接口实现遗漏。

现在从对应详情链接附近读取 `data-bg`、`data-original`、`data-src`、图片 src 和 CSS background-image，解析 HTML 实体与相对地址。DM84 使用的是 `<a data-bg>`，并没有 `<img>`。提取限定在同一番剧条目，避免无图条目借用相邻番剧的图片。

前端优先加载源图，失败时通过已有且需要认证的媒体代理拉取图片 Blob；请求携带认证，Blob 在组件卸载时释放。失败或无图时显示占位图。图片失败不会触发番剧搜索或集数加载失败。

DM84「辉夜」的 7 个 cover 均已返回；5 张图片为有效 JPEG，其中浏览器已实际显示。第三季图片源返回 404，辉夜姬物语图片源返回 403，直连、带 Referer、服务端代理结果一致。这两张是上游图片失效/拒绝访问，不能通过补字段恢复。

## 界面与添加操作

两类聚合源使用与 Emby/Jellyfin 相同的浏览组件、Modal、搜索、海报墙、选择和底部确认操作，并为番剧提供以下适配：

- 数据源、关键词、搜索按钮放在同一行。
- 不显示上级目录，使用「搜索结果 → 番剧名称」返回搜索结果。
- 番剧结果支持列表/海报墙；海报按容器宽度自动排列，独立滚动。
- 集数使用无海报的三列紧凑列表；窄屏为单列以保持可读。
- 点击集数仅选择，底部确认后添加；支持多选和整部添加。
- 添加失败保留失败选项；整部添加再次重试时只提交上次失败的集数。
- 过期搜索/数据源请求不会覆盖新结果；添加过程中阻止重复操作。

## 切换数据源后的全屏与关键词保留

2026-10-12 后续修复：番剧浏览器此前使用 `key={sourceId}`，切换源会重建浏览组件及 Modal，造成网页全屏退出、关键词丢失。现在保持组件实例，通过源上下文清理旧结果、目录和选择状态，保留全屏与输入内容。关键词非空时，切源后自动使用原关键词查询新源；空关键词不发请求，选择当前源也不会重复搜索。

番剧关键词与搜索结果视图状态分开管理，进入集数、返回搜索结果时也保留关键词。Emby/Jellyfin 默认关键词行为保持原有设置。搜索和目录请求各自检查请求序号，避免切源后旧请求晚返回覆盖新结果，或者让旧搜索的加载状态持续挂起。

验证：前端构建及 ESLint 通过；浏览器回归分别覆盖 Kazumi/ani-subs 的全屏切源、关键词保留、自动搜索、空关键词不请求、集数页切源、旧请求延迟返回，以及原有 120 条结果、3,600 集列表、批量确认和失败重试。自动搜索只在源实际切换时触发，输入关键词不会触发请求。
