# Cloudflare Tunnel 一键启动与更新说明

## 用户操作

服务总览的 FRP 快捷引导改为“新手推荐：Cloudflare Tunnel”，提示语为“一键启动，无需额外配置”，点击后进入连接方式页，Cloudflare 卡片排在首位。启动前最多等待 8 秒检查本机 `/health`；通过后才查询更新并启动 cloudflared。Cloudflare 分配候选地址后，程序连续两次从公网访问本机首页，均收到成功状态才公布地址。检查失败会停止这条隧道并提示原因，不自动换地址重试。运行中不再持续探测、不自动切换地址；用户可手动停止、复制地址或点击“刷新隧道”重启并获取新地址。

## 实现边界

- 版本和校验值来自 Cloudflare 官方 GitHub Release API，下载使用官方 Release 资产地址，并限制 HTTPS 与 GitHub 下载主机。
- 文件先下载到运行包目录的临时文件，检查 HTTP 状态、大小、Release SHA-256（若提供）和 Windows PE 标记后再替换；失败时清理临时文件并保留旧版。
- PATH 中的用户文件不会被改写；自动更新组件落在当前运行包的 `runtime/`。
- 每次启动检查官方版本。查询失败或更新失败时记录警告并继续使用现有组件；首次安装失败时显示错误。
- 启动前使用现有后端 `/health` 检查本机源站。得到候选 trycloudflare 地址后，以 HTTPS 请求公网首页，连续两次返回 2xx（每次请求最多 5 秒，整体检查最多 45 秒）才把地址设为运行中并显示给用户。
- 健康检测失败时停止候选进程、隐藏候选地址并显示最后一次失败原因；通过后结束探测，不做后台健康轮询或自动切换。
- “刷新隧道”在同一互斥操作中停止旧进程并重新执行启动/更新检查流程，避免同时建立多条受管隧道。
- “停止隧道”按钮使用红色背景；引导提示语统一为“一键启动，无需额外配置”。
- 隧道按当前实际网页协议与端口启动，不需要账号或额外隧道配置；快速隧道地址在进程停止后失效。

## 构建与检查

使用 `npm --prefix desktop run shell:build -- --release` 构建 Windows 桌面程序。构建产物为 `desktop/build/bin/ZViewerDesktop.exe`。本次提交只记录源码与说明，发行目录中的 exe 由该命令生成。
